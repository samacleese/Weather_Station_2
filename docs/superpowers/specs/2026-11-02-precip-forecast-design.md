# Precipitation Forecast Strip Design

**Date:** 2026-11-02
**Status:** Draft, awaiting Jesse's review

## Goal

Replace the METAR line at the bottom of the display with a 4-day chance-of-precipitation forecast. The METAR (`rawMessage`) is empty about 85% of the time, so the line is mostly wasted space.

Target rendering, one line along the bottom of the screen:

```
Precip:  Today 1%    Tue 0%    Wed 87%❄    Thu 25%
```

## weather.gov API

Forecasts are keyed by NWS gridpoint, not by observation station.

- **Endpoint:** `GET https://api.weather.gov/gridpoints/{wfo}/{x},{y}/forecast` (in `https://api.weather.gov/openapi.json`).
- **Gridpoint lookup (one-time, by hand):** `GET https://api.weather.gov/points/{lat},{lon}` → `properties.gridId`, `gridX`, `gridY`. For KBFI (47.5455, -122.3147) that gives `SEW/125,65`. Station coordinates come from `GET /stations/{id}` → `geometry.coordinates` (lon, lat order).
- **Response:** about 13–14 KB with 14 `properties.periods[]` alternating day and night (7 days). Fields used:
  - `startTime`: ISO 8601 with local offset, e.g. `2026-11-03T06:00:00-08:00`
  - `isDaytime`: bool
  - `probabilityOfPrecipitation.value`: integer percent, may be `null`
  - `shortForecast`: free text, e.g. `Light Snow Likely`, `Chance Rain And Snow`
- **Certificate:** same host, `api.weather.gov`, so the existing `CACerts` entry covers it.
- **Gotchas:**
  - After about 6pm local time, period 1 is `Tonight` and today has no daytime period left.
  - `name` can be `This Afternoon` or a holiday name (`Thanksgiving Day`), so labels are derived from `startTime`, not `name`.
  - `probabilityOfPrecipitation` covers *any* precipitation, not just rain. Hence the neutral `Precip:` label.

Verified live on 2026-11-02 against KBFI (`SEW/125,65`, rain) and a Cascades point (`SEW/166,121`, snow). Snow periods have exactly the same structure and numeric PoP as rain periods.

## Behavior

- **Days shown:** the first 4 periods with `isDaytime == true`. In the evening the strip starts at tomorrow.
- **Value per day:** that daytime period's `probabilityOfPrecipitation.value`. `null` displays as `--%`.
- **Label:** `Today` when the first daytime period starts on the same date as period 1; otherwise a 3-letter weekday (`Mon`…`Sun`) computed from the `YYYY-MM-DD` prefix of `startTime`. This uses pure date arithmetic (days-from-civil), with no dependence on system time or time zone.
- **Snow marker:** a snowflake bitmap goes after the percent when that daytime period's `shortForecast` contains `snow` (case-insensitive). `Rain And Snow Likely` → flake. `Chance Rain`, sleet and freezing rain → no flake.
- **Fewer than 4 daytime periods:** show what's there.
- **Failure:** if the forecast request or parse fails, the strip reads `Precip forecast unavailable`. A forecast failure doesn't affect the current-conditions error path, the warnings line, or the sleep interval.

## Components

### `PrecipForecast` (`src/network/PrecipForecast.h/.cpp`)

Modeled on `CurrentConditions`: takes an `IHttpClient&`, is host-testable, and uses an ArduinoJson `DeserializationOption::Filter`.

```cpp
struct PrecipDay {
    char label[6];   // "Today", "Tue"
    int percent;     // -1 when unknown
    bool snow;
};

class PrecipForecast {
   public:
    static const int MAX_DAYS = 4;
    PrecipForecast(IHttpClient& http, const std::string& gridpoint);
    int update();                            // PRECIP_FORECAST_OK or a negative error code
    const char* getErrorString(int errorCode);
    static void formatDay(const PrecipDay& day, char* buf, size_t len);  // "Wed 87%", "Thu --%"

    PrecipDay days[MAX_DAYS];
    int dayCount = 0;
    int lastError = PRECIP_FORECAST_OK;
};
```

- URL: `https://api.weather.gov/gridpoints/` + gridpoint + `/forecast`.
- Filter: `properties.periods[0].{startTime, isDaytime, probabilityOfPrecipitation, shortForecast}` (ArduinoJson applies the element-0 filter to every array element).
- Error codes follow `CurrentConditions`: OK, general, JSON, network, data missing, cert. Network results map the same way (`-5` → cert error). That mapping is shared with `CurrentConditions` through a small helper, so it isn't copied.
- Logging uses a new shared header `src/network/NetworkLog.h` (the `#ifdef ARDUINO` ArduinoLog-or-no-op macros now inlined in `CurrentConditions.cpp`), adopted by both clients.
- `PrecipForecast::update()` makes one request, with no retry loop of its own (unlike `CurrentConditions::update(3)`), though the network layer's own retries (`WeatherNetwork::get`) still apply. A failure costs one strip of text, not the whole screen.

### Snowflake bitmap (`src/display/Snowflake.h`)

- Generated by a new `tools/glyph_to_bitmap.py`, which renders a single glyph with Pillow (already in `requirements.txt`) into a 1-bit, row-major, MSB-first PROGMEM array with width/height constants. That's the format `Adafruit_GFX::drawBitmap` expects.
- CLI: `--font PATH --char CHAR --size PX --name IDENT --out PATH`, with `--help` text explaining when to use it.
- Source glyph: U+2744 ❄ from `DejaVuSans.ttf`, sized to roughly the cap height of the 42 pt strip font (finalized on device).
- The generated header starts with ABOUTME lines and a comment recording the exact command used to create it.
- Why not the Roboto GFX fonts? They come from a web generator, are ASCII-only, and have no ❄ glyph.

### Display wiring (`Weather_Station_2.ino`)

After the current-conditions fetch:

1. Construct `PrecipForecast(*network, WEATHER_FORECAST_GRIDPOINT)` and call `update()`.
2. At `LAYOUT_MAIN_PRECIP_FORECAST_X/Y` in `Roboto_Medium.at(LAYOUT_MAIN_PRECIP_FORECAST_FONT_SIZE)`: print `Precip:`, then for each day print `formatDay()`. If `snow`, draw the snowflake at the cursor (bottom-aligned to the baseline) and advance the cursor past it. Then add a fixed gap before the next day.
3. On failure, print `Precip forecast unavailable` at the same position.

The full-error screen (no current conditions at all) is unchanged. The forecast is fetched only after that early return, so a network failure doesn't pay for a second fetch.

### METAR removal

Remove `raw_message`, the `rawMessage` filter entry, and the cached `raw_message` from `CurrentConditions`, along with the tests that cover them. Nothing displays the METAR anymore.

### Layout

Rename the `metar` field to `precip_forecast` (start: `x: 20, y: 780, font_size: 42`, tuned on device; `font_size` must be one of the Roboto sizes in `assets/fonts/*.h`, since `.at()` throws on any other) in all four places: `layout.json`, `cmake/Layout.cmake`, `src/layout.h.in`, `tools/layout-editor/index.html`.

### Config

New required setting `WEATHER_FORECAST_GRIDPOINT` (e.g. `"SEW/125,65"`; `CMakeLists.txt` fails configure with a clear message if it is missing, so an old `config.cmake` can't silently produce an empty URL) in `config.cmake.example` (with a comment showing the `/points` lookup), `src/user_settings.h.in`, and wherever CMake reads `WEATHER_STATION_ID`. Jesse's local `config.cmake` and any worktree copies need the new line.

## Testing

TDD throughout.

**Host gtest (`tests/unit/PrecipForecastTest.cpp`, `./build.sh test-host`)**, using `StubHttpClient` and real captured responses as fixtures:

- KBFI morning fixture → `Today 1%`, `Tue 0%`, `Wed 87%`, `Thu 25%`, no snow.
- Evening response (period 1 is `Tonight`) → the first label is tomorrow's weekday.
- Cascades fixture → snow flagged for Wed (`Mostly Sunny then Rain And Snow Likely`) and Thu (`Light Snow Likely`); not for Today/Tue (`Partly Sunny`). Matching is case-insensitive.
- Holiday-named period → label is still the weekday.
- Null PoP → `percent == -1` and `formatDay` gives `--%`.
- Fewer than 4 daytime periods → `dayCount` matches.
- Empty body, malformed JSON, missing `properties`, network error, cert error → correct codes and `dayCount == 0`.
- URL is built from the gridpoint.
- Weekday arithmetic is checked against known dates.
- `CurrentConditions` tests are updated for the METAR removal.

**Python (`tests/python/test_glyph_to_bitmap.py`, `./build.sh test-python`):** output dimensions, row padding/bit order, header text, and errors for a missing font or a blank glyph. A glyph absent from the font renders as the font's placeholder box, which can't be told apart reliably, so the tool prints an ASCII preview to check by eye instead.

**Hardware:**

- `./build.sh build`, `./build.sh flash`, then `python3 tools/serial_capture.py --seconds 40`: two `[HTTPS] GET... code: 200` lines, and the strip renders.
- Snow check: temporarily set `WEATHER_FORECAST_GRIDPOINT` to `SEW/166,121` (Cascades), confirm the flakes render and line up, then set it back.
- Tune x/y/font in the layout editor if the strip crowds the description.

## Out of scope

- Runtime gridpoint lookup.
- Night-period values or max of day and night.
- Distinguishing sleet or freezing rain.
- Caching the forecast across deep sleep.
